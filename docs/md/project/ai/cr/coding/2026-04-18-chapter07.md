经过前面几个章节的实现，又完善了AI智能代码审查系统的CodeReview服务层的功能，能够生成CR记录和日报，对接微信-钉钉-飞书-自定义WebHook实现了发送通知消息。并且设计和实现了基于Gitea、Github和Gitlab三大类型代码仓库的核心WebHook，分别对Gitea、Github和Gitlab的Push和PR/MR等代码的Code Review进行了设计和实现。

## 一、整体进展回顾

在开始之前，先快速回顾一下项目目前已完成的进度。

### 第一阶段：基础配置与数据层（已完成）

**配置类**

- `AsyncConfig`：异步任务线程池配置
  - 核心线程池：5个
  - 最大线程池：20个
  - 队列容量：100个
  - 拒绝策略：CallerRunsPolicy

- `WebConfig`：Web MVC配置
  - 静态资源处理
  - CORS配置

- `AiReviewConstants`：全局常量管理
  - HTTP请求头定义（Authorization、Accept等）
  - Webhook事件类型（ACTION_OPENED、ACTION_SYNCHRONIZE等）
  - 审查类型标签（REVIEW_TYPE_PULL_REQUEST、REVIEW_TYPE_PUSH）
  - 业务消息常量
  - Markdown格式常量
  - 环境变量Key前缀

**数据层**

- `MrReviewLog`：MR审查日志实体（JPA + Builder模式）
- `PushReviewLog`：Push审查日志实体（JPA + Builder模式）
- `MrReviewLogRepository`：MR数据访问层
  - 多条件过滤查询方法
  - 聚合查询方法（统计不同作者、项目）
- `PushReviewLogRepository`：Push数据访问层（相同查询接口）

### 第二阶段：LLM客户端层（已完成）

**核心类**

- `BaseOpenAIClient`：LLM客户端抽象基类
  - HTTP请求封装
  - 超时配置（连接30秒，读取30秒）
  - 重试逻辑（最多3次）
  - JSON响应解析

- `LLMClient`：统一LLM接口
  - 定义completions标准方法

- `LLMFactory`：客户端工厂类
  - 根据配置创建对应的LLM客户端
  - 支持OpenAI、DeepSeek、Qwen、GLM四种模型

**具体实现**

- `OpenAIClient`：OpenAI API客户端
  - 默认模型：gpt-3.5-turbo
  - 支持自定义base-url

- `DeepSeekClient`：DeepSeek API客户端
  - 默认模型：deepseek-chat
  - 支持自定义base-url

- `QwenClient`：通义千问API客户端
  - 默认模型：qwen-turbo
  - 支持自定义base-url

- `GlmClient`：智谱GLM API客户端
  - 默认模型：glm-4.7-flash
  - 支持自定义base-url

### 第三阶段：通知服务层（已完成）

**服务接口**

- `NotificationService`：通知服务接口
  - `sendReviewNotification`：发送代码审查结果通知（重载2个版本）
  - `sendDailyReport`：发送日报通知
  - `sendErrorNotification`：发送错误通知

**服务实现**

- `NotificationServiceImpl`：通知服务实现类
  - 集成4个Notifier实现多渠道通知
  - 统一构建通知消息格式
  - 支持Markdown和Text两种消息类型
  - 处理消息长度限制和内容截断

**四个Notifier实现**

- `DingTalkNotifier`：钉钉通知器
  - 支持按项目名或URL slug路由不同的webhook URL
  - 支持Markdown和Text两种消息类型
  - 支持atAll功能
  - 环境变量配置：`DINGTALK_WEBHOOK_URL`、`DINGTALK_WEBHOOK_URL_{PROJECT_NAME}`、`DINGTALK_WEBHOOK_URL_{URL_SLUG}`

- `WeComNotifier`：企业微信通知器
  - 支持按项目名或URL slug路由不同的webhook URL
  - **智能内容分割**：Markdown类型最大4096字节，Text类型最大2048字节，超长内容自动分割发送
  - **内容格式化**：自动处理标题、链接、HTML标签等
  - 环境变量配置：`WECOM_WEBHOOK_URL`、`WECOM_WEBHOOK_URL_{PROJECT_NAME}`、`WECOM_WEBHOOK_URL_{URL_SLUG}`

- `FeishuNotifier`：飞书通知器
  - 支持按项目名或URL slug路由不同的webhook URL
  - **使用飞书2.0卡片格式**，支持header和body结构
  - **丰富的卡片配置**：支持PC和移动端自适应、文本大小配置
  - 环境变量配置：`FEISHU_WEBHOOK_URL`、`FEISHU_WEBHOOK_URL_{PROJECT_NAME}`、`FEISHU_WEBHOOK_URL_{URL_SLUG}`

- `ExtraWebhookNotifier`：扩展Webhook通知器
  - 发送自定义扩展消息
  - 将系统数据（ai_codereview_data）和原始webhook数据（webhook_data）一起发送
  - 支持自定义webhook URL

### 第四阶段：业务逻辑层（已完成）

**核心服务**

- `ReviewService`：审核服务接口和实现类
  - `insertMrReviewLog`：保存MR审查日志
  - `insertPushReviewLog`：保存Push审查日志
  - `getMrReviewLogs`：查询MR审查日志（支持多条件过滤）
  - `getPushReviewLogs`：查询Push审查日志（支持多条件过滤）
  - `getMrDistinctAuthors`：获取MR distinct作者列表
  - `getMrDistinctProjectNames`：获取MR distinct项目名称列表
  - `getPushDistinctAuthors`：获取Push distinct作者列表
  - `getPushDistinctProjectNames`：获取Push distinct项目名称列表

- `CodeReviewService`：代码审查服务接口和实现类
  - `reviewAndStripCode`：审查代码并去除markdown格式
  - `detectLanguageFromDiff`：从diff文本中检测主要编程语言
  - `parseReviewScore`：解析AI返回的审查结果中的分数

**代码审查逻辑**

- **语言检测**：通过文件路径（diff --git a/xxx b/xxx）和代码特征（如setup()、ref()、<template>等）检测编程语言
- **支持语言**：Python、JavaScript/TypeScript、Java、Vue3、Go、PHP、C/C++
- **Token限制**：简单估算1 token ≈ 4 chars，超过限制自动截断
- **提示词模板**：支持Jinja2语法，根据审查风格（专业、讽刺、温和、幽默）动态调整

**ReportService**：日报生成服务

- 定时任务调用
- 查询今日审查记录
- 统计分析（作者、项目、评分等）
- 生成图表和总结

### 第五阶段：Git平台集成层（已完成）

**三个Webhook Handler**

- `GitHubWebhookHandler`：GitHub平台适配器
- `GitLabWebhookHandler`：GitLab平台适配器
- `GiteaWebhookHandler`：Gitea平台适配器

**GitHub实现要点**

- 支持PR事件类型：opened、synchronize、edited
- **分支过滤**：支持仅审查指定分支（逗号分隔，如`main,develop`）
- **受保护分支过滤**：通过GitHub API检查受保护分支
- **代码行数统计**：自动计算新增和删除的代码行数
- **PR评论发布**：自动在PR中发布AI审查结果
- **Push审查**：支持Push事件审查（需配置review.push-enabled）
- **分页获取文件**：GitHub API单次最多返回100个文件，支持分页

## 二、本节实现内容详细说明

### 2.1 application.yml - SpringBoot主配置文件

#### 2.1.1 服务器配置

```
server:
  port: ${SERVER_PORT:5002}
```

- 端口默认为5002，可通过环境变量`SERVER_PORT`修改

#### 2.1.2 数据源配置

```
spring:
  datasource:
    url: ${DB_URL}
    driver-class-name: ${DB_DRIVER:com.mysql.cj.jdbc.Driver}
    username: ${DB_USER:root}
    password: ${DB_PASSWORD:root}
  jpa:
    database-platform: ${DB_PLATFORM:org.hibernate.dialect.MySQLDialect}
    hibernate:
      ddl-auto: update
    show-sql: false
    properties:
      hibernate:
        format_sql: false
```

- 支持通过环境变量配置数据库连接
- 默认数据库名：ai_review
- `ddl-auto: update`：自动更新数据库表结构
- `show-sql: false`：不显示SQL语句

#### 2.1.3 LLM配置

```
llm:
  provider: ${LLM_PROVIDER:glm}  # 默认使用GLM模型
  openai:
    api-key: ${OPENAI_API_KEY:}
    base-url: ${OPENAI_API_BASE_URL:https://api.openai.com/v1}
    model: ${OPENAI_API_MODEL:gpt-3.5-turbo}
  deepseek:
    api-key: ${DEEPSEEK_API_KEY:}
    base-url: ${DEEPSEEK_API_BASE_URL:https://api.deepseek.com}
    model: ${DEEPSEEK_API_MODEL:deepseek-chat}
  qwen:
    api-key: ${QWEN_API_KEY:}
    base-url: ${QWEN_API_BASE_URL:https://dashscope.aliyuncs.com/compatible-mode/v1}
    model: ${QWEN_API_MODEL:qwen-turbo}
  glm:
    api-key: ${GLM_API_KEY:}
    base-url: ${GLM_API_BASE_URL:https://open.bigmodel.cn}
    model: ${GLM_API_MODEL:glm-4.7-flash}
```

- 支持4种LLM提供商，通过`llm.provider`选择
- 所有API Key都支持通过环境变量配置
- 每个提供商都支持自定义base-url和模型名称

#### 2.1.4 Git平台配置

```
gitlab:
  access-token: ${GITLAB_ACCESS_TOKEN:}
  url: ${GITLAB_URL:https://gitlab.com}

github:
  access-token: ${GITHUB_ACCESS_TOKEN:}
  url: ${GITHUB_URL:https://api.github.com}

gitea:
  access-token: ${GITEA_ACCESS_TOKEN:}
  url: ${GITEA_URL:}
  use-issue-mode: ${GITEA_USE_ISSUE_MODE:true}
```

- GitLab和GitHub：配置access-token和API URL
- Gitea：支持issue模式（将审查结果发布到issue而不是comment）
